# Security Policy

This document outlines the security model, data protection mechanisms, and Content Security Policy (CSP) guidelines implemented in **Prakriti** to protect user inputs, API credentials, and local states.

## Security Model

Prakriti follows a privacy-first, secure-by-default architecture:

1. **Local-First Fallback:** All user logs, budgets, and onboarding selections are saved locally on the client machine using `localStorage` if Supabase environment variables are missing. This keeps data entirely private to the user's browser.
2. **Secure Credentials:** Outbound calls to Google's Gemini API are proxy-routed through Next.js server-side endpoints (`src/app/api/scan/route.ts` and `src/app/api/insights/route.ts`). The `GEMINI_API_KEY` is kept server-side as an environment variable and is never exposed to the client-side JavaScript bundle.
3. **Data Integrity (Zod):** Untrusted input from local storage and external APIs is strictly validated using Zod schemas at runtime to prevent prototype pollution or database injection.

## Content Security Policy (CSP)

Prakriti implements a strict Content Security Policy (CSP) with dynamic per-request nonces.

### Directive Rules
- **script-src:** Restricted to `'self'` and script tags marked with the dynamic `'nonce-{nonce}'` generated by `middleware.ts`. In development mode, `'unsafe-eval'` is allowed to preserve Hot Module Replacement (HMR).
- **style-src:** Restricted to `'self'` and `'unsafe-inline'` to accommodate tailwind inline utility injections.
- **img-src:** Restricted to `'self'`, raw base64 data URLs (`data:`), and camera capture buffers (`blob:`).
- **connect-src:** Restricts outgoing connections to:
  - `'self'` (the Next.js server)
  - `*.supabase.co` (Supabase database endpoints)
  - `generativelanguage.googleapis.com` (Google Gemini API endpoints)
  - Local WebSocket sockets (`ws://localhost:*`, `wss://localhost:*`) in development mode for hot reloads.
- **Permissions-Policy:** The browser permissions policy restricts camera usage exclusively to the application origin (`camera=self`), protecting users against hijack capture.

## Security Headers

Next.js is configured via `next.config.mjs` to inject standard security headers on every response:
- `X-Frame-Options: DENY` (prevents clickjacking)
- `X-Content-Type-Options: nosniff` (prevents MIME-type sniffing)
- `Referrer-Policy: strict-origin-when-cross-origin` (restricts referrer leakages)
- `X-XSS-Protection: 1; mode=block` (activates browser XSS filters)

## Reporting a Vulnerability

If you discover a security vulnerability within this project, please report it immediately:
1. **Do not** open a public GitHub issue.
2. Email your report with details, reproduction steps, and potential impact to **security@prakriti-carbon.org**.
3. We will acknowledge receipt within 24 hours and coordinate a patch within 7 business days.
